# Klinglab Stream Mixer Remote Protocol v1

実装の根拠は [SPEC.md](SPEC.md) の第9〜13章です。本書はミキサー本体と Stream Deck プラグインの通信形式を定義します。本体のサーバーは M7 で実装しました。`streamdeck/mock-server/` は本体を起動せずに表示と通信を確認するために使えます。デバイス変更を伴うプロジェクト切り替えには未解決の制約があります。末尾を参照してください。

## 接続とバージョン

- 接続先は `ws://127.0.0.1:47321/`。サーバーは IPv4 のループバックだけに bind します。認証・外部公開・音声転送はありません。
- 1フレームに1つの UTF-8 JSON オブジェクトを送ります。バイナリは受け付けません。最大サイズは 1 MiB です。
- 全メッセージの `version` は整数 `1`。これは通信のバージョンです。`state.mixerVersion` はアプリの表示用バージョンです。
- 接続直後、サーバーが要求を待たずに全状態を送ります。クライアントはこれを受け取るまで操作を送りません。5秒以内に受信できなければ接続を閉じます。
- バージョンが一致しない場合、クライアントは全ボタンに `UPDATE MIXER` と表示し、要求を送りません。押すと `showAlert` だけを実行します。接続を閉じ、2秒後に再接続します。次の有効な全状態を受け取るまで表示を保ちます。プラグインが古い場合も同じ表示です。導入時には両方のバージョンを確認してください。
- サーバーは不一致の要求に `VERSION_MISMATCH` を返し、コード `1002` でその接続を閉じます。本体の処理は止めません。
- 切断や接続失敗の2秒後に再接続します。再接続のたびに全状態を受け取り直します。通常の切断中は `MIXER OFF` と表示します。
- 切断中・同期前・送信が詰まっている間の操作は破棄します。再送・接続待ちのキューは作りません。送信済みでも応答が不明な操作は再送しません。
- サーバーは10秒ごとに WebSocket ping を送り、次の周期まで pong が無ければその接続を閉じます。クライアントは ping またはメッセージを35秒受信しなければ接続を閉じます。
- ブラウザーからの接続は受け付けません。`Origin` ヘッダー付きの upgrade は拒否します。これはローカルのネイティブクライアント向けです。

## 全状態

```json
{
  "type": "state",
  "version": 1,
  "revision": 0,
  "state": {
    "mixerVersion": "0.1.0",
    "fxChain": [
      { "n": 1, "name": "Voice EQ", "bypass": false },
      { "n": 2, "name": "Voice Compressor", "bypass": true }
    ],
    "streamFx": [
      { "n": 1, "name": "Bus EQ", "bypass": false }
    ],
    "projects": {
      "slots": [
        { "n": 1, "name": "Talk" },
        { "n": 2, "name": "Song" },
        { "n": 3, "name": null },
        { "n": 4, "name": null },
        { "n": 5, "name": null },
        { "n": 6, "name": null },
        { "n": 7, "name": null },
        { "n": 8, "name": null },
        { "n": 9, "name": null }
      ],
      "current": { "n": 1, "name": "Talk" },
      "loading": null
    },
    "bgm": [
      { "n": 1, "name": "Opening", "playing": false },
      { "n": 2, "name": "Break", "playing": false }
    ],
    "se": [
      { "n": 1, "name": "Bell", "playing": false },
      { "n": 2, "name": "Applause", "playing": false }
    ],
    "loud": {
      "on": false,
      "mode": "STREAM",
      "learning": false,
      "remainingSeconds": 0,
      "learnedDb": 4.3
    }
  }
}
```

| フィールド | 定義 |
|---|---|
| `revision` | サーバー全体の状態更新番号。0以上の安全な整数。変更ごとに1増えます。接続し直した場合は直前の接続の値と比較しません。 |
| `mixerVersion` | 空でない文字列。 |
| `fxChain`, `streamFx` | 現在の列の全スロット。`n` は並び順の1始まりの安全な整数、`name` は空でない名前、`bypass` は真偽値。`false` がエフェクト ON。9個を超える列も送信します。FX CHAIN のボタン設定は1〜9です。 |
| `projects.slots` | 必ず番号1〜9の9要素。未登録の名前は `null`。 |
| `projects.current` | 現在の名前と登録番号。登録外の保存済みプロジェクトは `{ "n": null, "name": "名前" }`。未保存なら `null`。 |
| `projects.loading` | 読み込み中の登録番号1〜9。完了・失敗後は `null`。現在のプロジェクトは完了まで変えません。 |
| `bgm`, `se` | 登録済み項目の全一覧。`n` は1始まりの安全な整数、`name` は空でない名前、`playing` は真偽値。空番号は一覧に含めません。停止完了や自然終了でも更新します。 |
| `loud.on` | LOUD の ON/OFF。 |
| `loud.mode` | `STREAM` または `CD`。 |
| `loud.learning` | 測定中なら `true`。LOUD OFF でも測定できます。 |
| `loud.remainingSeconds` | 0〜20の整数。開始時は20、測定中は1秒ごとに残りを切り上げて通知し、終了時は0。 |
| `loud.learnedDb` | 覚えた量、単位 dB。有限の数値。CD の +4.5 dB は含めません。 |

一覧の `n` は昇順で重複させません。プラグインの追加・削除・並べ替えや、サウンドの名前変更・並べ替えでも更新します。名前は最大256 Unicode コードポイントです。クライアントは描画時に XML をエスケープします。

## 差分イベント

```json
{
  "type": "event",
  "version": 1,
  "revision": 1,
  "changes": {
    "fxChain": [
      { "n": 1, "name": "Voice EQ", "bypass": true },
      { "n": 2, "name": "Voice Compressor", "bypass": true }
    ]
  }
}
```

`changes` は変更した最上位フィールドだけを含みます。値はそのフィールド全体を置き換えます。配列の部分更新や再帰マージはしません。使えるキーは `mixerVersion`, `fxChain`, `streamFx`, `projects`, `bgm`, `se`, `loud` です。空の `changes` は送りません。同じ変更は全クライアントへ同じ番号で通知します。本体の GUI・ショートカット・音源の自然終了・測定タイマーによる変更も通知します。

クライアントは `revision` が直前の値+1の場合だけ差分を適用します。番号の欠落・重複・逆行、不正な必須フィールド、未知のメッセージ型では状態を捨て、接続を閉じて全状態から同期し直します。同じ接続では全状態を1回だけ送ります。同じバージョン内の未知の追加フィールドは無視します。

## 操作要求

```json
{ "type": "request", "version": 1, "id": "17", "command": "toggleFx", "n": 1 }
```

`id` は接続内で重複しない1〜64文字の英数字・`-`・`_`です。応答との対応にだけ使います。サーバーはこの値を操作の再送・重複排除には使いません。クライアントは未応答の要求を最大32件まで持ち、5秒で時間切れにします。時間切れ時は警告を出して接続を閉じ、状態を再同期します。

| `command` | 引数 | 動作 |
|---|---|---|
| `toggleFx` | `n`: 1〜9 | FX CHAIN のその番号の `bypass` を反転。 |
| `loadProject` | `n`: 1〜9 | 登録済みプロジェクトを読み込み。最初に `loading=n` を通知。準備が終わったら構成・LOUD・`current` と `loading=null` を同じイベントで通知。 |
| `toggleStreamFx` | `n`: 正の安全な整数 | STREAM FX の `bypass` を反転。 |
| `playBgm` | `n`: 正の安全な整数 | 再生中なら1秒で停止。別曲なら前の曲を1秒でフェードアウトして切り替え。 |
| `playSe` | `n`: 正の安全な整数 | 再生／停止。同時16音まで。 |
| `stopSounds` | `kind`: `bgm` / `se` / `all` | 対象を停止。BGM は1秒フェード、SE は即停止。鳴っていなくても成功。 |
| `loudToggle` | なし | `loud.on` を反転。 |
| `loudLearn` | なし | 測定開始／終了。最長20秒。終了時は `learnedDb` を更新。音が小さすぎる場合は前の量を保つ。 |
| `loudMode` | なし | `STREAM` と `CD` を反転。 |

余分な要求フィールドは無視します。番号は整数だけを受け付け、文字列を数値へ変換しません。番号が範囲内でも項目が無ければ `EMPTY_SLOT`、引数の型や範囲が違えば `INVALID_ARGUMENT` です。

成功時は要求元に次を返します。これは受け付けたことを示します。クライアントはこの応答から表示を変えず、全状態・差分イベントだけを使います。

```json
{ "type": "result", "version": 1, "id": "17", "ok": true }
```

即時操作ではイベントを先に送り、次に成功応答を返します。プロジェクト読み込みは開始イベントの後に成功応答を返し、完了イベントを後で送ります。切り替えに成功した場合、進行中の LOUD 測定は取り消し、新しいプロジェクトの覚えた量を使います。失敗した場合は測定を含む現在の状態を保ちます。読み込み中の次の `loadProject`、BGM の切り替え待ち中の次の `playBgm` は `BUSY` とします。ほかの操作は引き続き受け付けます。`stopSounds` は BGM の切り替え待ちも取り消します。停止していない種類の再生は変えません。

## エラー応答

```json
{
  "type": "result",
  "version": 1,
  "id": "18",
  "ok": false,
  "error": { "code": "EMPTY_SLOT", "message": "この番号には登録がありません。" }
}
```

| `error.code` | 条件 |
|---|---|
| `VERSION_MISMATCH` | 通信バージョンが不一致。 |
| `INVALID_MESSAGE` | JSON が不正、オブジェクトでない、型・id・command が不正。対応可能な id が無ければ `id:null`。 |
| `INVALID_ARGUMENT` | 引数の型・値が不正。 |
| `UNKNOWN_COMMAND` | 存在しないコマンド。 |
| `EMPTY_SLOT` | その番号が空。 |
| `BUSY` | その機能が読み込み・切り替え中。 |
| `LIMIT_REACHED` | SE の同時再生数を超える。 |
| `TOO_QUIET` | 測定に必要な、−70 LUFS より上の音が3秒分無い。 |
| `LOAD_FAILED` | プロジェクトの準備に失敗。現在の状態を保ち、`loading` を解除。 |
| `INTERNAL_ERROR` | 該当の要求を処理できない。ほかの接続や本体は動作を継続。 |

`message` は利用者向けの日本語です。要求に対応するエラーではボタンに `showAlert` を出します。自動終了時の `TOO_QUIET` や非同期の `LOAD_FAILED` は全クライアントへ `type:"error"`, `version:1`, `error:{code,message}` を送り、その機能のボタンに警告を出します。測定・読み込みの終了イベントを先に送ります。

大きすぎるフレームは `1009`、バイナリは `1003` でその接続だけを閉じます。1秒に30要求を超えた接続は `1008` で閉じます。エラーでプロセス全体を終了しません。

## Stream Deck の表示

番号・名前と状態は受信した値から生成します。押した直後に ON/OFF を先回りして変えません。

| アクション | 表示 |
|---|---|
| FX On/Off | `bypass=false` でオレンジのランプ、`true` で灰色。 |
| Project | 読み込み中の番号に上部のオレンジ帯。現在の番号には `CURRENT`。 |
| STREAM FX On/Off | ON で緑のランプ。 |
| BGM / SE | 再生中に青緑／ピンクの帯。 |
| Stop Sounds | 選んだ対象が再生中ならオレンジの帯。 |
| LOUD On/Off | ON でオレンジの帯。 |
| LOUD Learn | 測定中は緑の帯と `STOP 秒数`。 |
| LOUD Mode | `STREAM` / `CD` と現在の強さ。強さは `learnedDb` に、CD なら4.5 dBを足した値。CD ではオレンジ。LOUD OFF のときも設定値を表示。 |

空番号・不正な設定は `-`。押しても要求は送らず `showAlert` だけを出します。切断中も要求を送らず、警告だけを出します。タイトルにも番号・名前、または接続状態を設定します。

## 模擬サーバーの範囲

`npm run mock` はこの形式で全状態・差分・応答を送ります。BGM は停止・切り替えに1秒、プロジェクトの準備に300 msをかけます。SE は3秒で自然終了します。BGM は8秒で自然終了します。LOUD は1秒ごとに残りを通知し、終了時は模擬入力の値から量を決めます。音声ファイルの再生・DSP・LUFS の実測・プロジェクトファイルの読み込みは行いません。

`--quiet` では `TOO_QUIET`、`--fail-project` では `LOAD_FAILED` を確認できます。`--version=2` はバージョン不一致の確認用です。`--port=番号` で確認用ポートを変更できます。これらは模擬サーバー専用の起動オプションで、通信への追加コマンドではありません。

## 本体の実装状況

本体は上記のフィールドをメッセージスレッドでまとめ、WebSocket と JSON の処理を音声コールバックの外で行います。GUI、ホットキー、プロジェクトの切り替え完了、サウンドの自然終了、LOUD の測定終了を同じ状態更新へ接続しました。LOUD の手動停止は音声側の結果を待ち、4秒で完了しなければ `INTERNAL_ERROR` を返します。

実サーバーへ9種類の要求を送る確認は、音声デバイスを開かない `--diagnostic` で行いました。プラグインの準備失敗では現在の列と LOUD 測定を保持し、成功時は測定を取り消して保存値へ切り替わることを確認しました。即時操作とプロジェクト読み込みの通知順序、2接続への同一 revision の配信、pong が無い接続の切断も確認済みです。

デバイス設定が異なる場合は I/O を停止して開き直すため、SPEC 第9章の無音断切り替えを満たしていません。デバイスの開始失敗も `selectDevices` の戻り値へ反映されず、ハードウェアまで含めた失敗時の保持と `LOAD_FAILED` は未対応です。同じデバイス設定の再適用では I/O を開き直しません。M7 全体の完了判定には、この制約の解消と実経路での確認が必要です。
