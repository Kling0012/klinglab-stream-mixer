# Klinglab Stream Mixer for macOS — 仕様書 v1

作成: Claude（2026-10-28）。この文書は実装の唯一の根拠です。

## 0. クリーンルームの約束（全作業者が守る）

- このアプリは、ある Windows 用配信ミキサーの**公開されている利用者向け説明書の機能**を参考に、Claude が仕様だけを書き起こしたものです。
- 実装者は、元の Windows ソフト（インストーラー、exe、dll、説明書 PDF、スクリーンショット）を**見ない・入手しない・解析しない**。この仕様書と、一般に公開された技術文書（Apple、JUCE、OBS、Elgato の SDK 文書）だけを使う。
- 元ソフトの名前、ロゴ、画像、文章をコードにも UI にも入れない。

## 1. 概要

配信者（VTuber・歌枠）向けのリアルタイム音声ミキサー。マイクの声と、他のアプリの音（カラオケ音源など）をまとめて OBS に送り、同時に自分のヘッドホンへ別バランスの返しを出す。

- 対象: macOS 14.4 以降（Core Audio Process Tap を使うため）、Apple Silicon と Intel（universal binary）。
- 技術: C++20、JUCE 8（CMake、FetchContent でバージョン固定）。アプリのライセンスは AGPL-3.0（JUCE 8 の無償ライセンス条件に合わせる）。OBS プラグインは GPL-2.0-or-later（libobs にリンクするため）。
- 設定保存先: `~/Library/Application Support/Klinglab Stream Mixer/`（settings.json、projects/、sounds/、plugin-list.xml、logs/）。
- UI 言語: ミキサー上のラベルは英大文字（INST INPUT、STREAM など下記のとおり）。ダイアログ・メニュー・説明・エラーは日本語。
- 名前: アプリ `Klinglab Stream Mixer`、bundle id `site.klinglab.streammixer`、OBS ソース名 `Klinglab Stream Mixer`。

## 2. 信号の流れ

```
[INST 源] APP（最大8アプリ）または CABLE（入力デバイス）
      │
      ├─ INST INPUT メーター（入ってきた大きさ。フェーダーなし）
      ├─▶ INST MON フェーダー ─────────────────────────────▶ MONITOR 合成
      └─▶ 遅延補正（自動＋手動 ±5ms 単位）─▶ STREAM INST フェーダー ─┐
                                                                 │
[MIC INPUT] ─▶ NR ─▶ FX CHAIN（声用プラグイン列）─┬─▶ STREAM VOCAL フェーダー ─┤
                                                ├─▶ VOCAL MON（MON スイッチ、MON WET）▶ MONITOR 合成
                                                └─▶ MIC MON OUT つまみ ─▶ MIC MON OUT デバイス
                                                                 │
                         STREAM バス = INST + VOCAL ─▶ STREAM FX（全体用プラグイン列）─▶ LOUD（上げ幅）─┐
                                                                                                    │
[BGM プレイヤー] ─▶ BGM STREAM フェーダー ───────────────────────────────────────────────────────────┤
                └─▶ BGM MON フェーダー（MON スイッチ）▶ MONITOR 合成                                   │
[SE プレイヤー]  ─▶ SE STREAM フェーダー ────────────────────────────────────────────────────────────┤
                └─▶ SE MON フェーダー（MON スイッチ）▶ MONITOR 合成                                     │
                                                                                                    ▼
                                                     MASTER フェーダー ─▶ 天井（LOUD ON 時のみ）─▶ 配信出力
                                                                                     ├─▶ OBS（共有メモリ）
                                                                                     └─▶ STREAM OUT デバイス（任意）
MONITOR 合成 ─▶ MONITOR OUT デバイス（STREAM FX・LOUD・MASTER はかからない）
```

要点:
- 「自分に聞こえる音（MONITOR）」と「配信に乗る音（STREAM）」は完全に別。返し側のフェーダーを動かしても配信は変わらず、逆も同じ。
- STREAM FX と LOUD の上げ幅は INST＋VOCAL にだけかかる。BGM・SE にはかからない。天井（リミッター）は BGM・SE を含めた配信出力全体にかかる。
- MASTER は配信出力全体（BGM・SE を含む）にかかる。
- 声の返し（VOCAL MON）は最小遅延。NR は遅延を足さない。プラグインが無いときは処理を素通りして遅延を足さない。
- 配信側では、FX CHAIN のプラグイン遅延（JUCE の getLatencySamples の合計）分だけ INST を自動で遅らせ、声とオケを揃える。STREAM FX はまとめた後にかかるのでずれない。手動補正 ±5ms 単位（−方向は自動補正量を下回らない範囲で INST を前に出す）。
- 内部は 32bit float、ステレオ。マイクがモノラルなら両チャンネルに複製。サンプルレートは MIC INPUT デバイスに従う（44.1/48/96k）。

## 3. デバイス（オーディオ入出力）

### 3.1 デバイス欄（画面上部の左ブロック）
| 欄 | 内容 | 必須 |
|---|---|---|
| INST INPUT | 左の小欄で `APP` / `CABLE` を選ぶ。APP のとき右欄はアプリ選択（4章）、CABLE のとき右欄は入力デバイス選択（BlackHole 等） | APP 既定 |
| MIC INPUT | 入力デバイス。複数チャンネル機器は使うチャンネル（1、2、1+2）を選べる | 必須 |
| MONITOR OUT | 出力デバイス（ヘッドホン） | 必須 |
| STREAM OUT | 出力デバイス（任意、空欄可）。OBS 以外のソフトへ配信音を出す | 任意 |
| MIC MON OUT | 出力デバイス（任意、空欄可）＋右に MIC MON つまみ（0.00〜2.00、既定 1.00、線形倍率表示）。声だけを Discord 等へ渡す（BlackHole 等に出す） | 任意 |

- 空欄は「(empty)」表示。
- 同じ仮想デバイスを INST(CABLE) と STREAM OUT の両方に選ぶとループするので、保存前に警告を出して拒否する。
- デバイスが抜けたら該当経路を無音にし、欄を赤くする。同じ名前（UID）のデバイスが戻ったら自動で再接続する。

### 3.2 オーディオエンジン
- MIC INPUT と MONITOR OUT は、アプリ内専用の private aggregate device（`AudioHardwareCreateAggregateDevice`、`kAudioAggregateDeviceIsPrivateKey=1`、MIC をクロックマスター、ドリフト補正 ON）でまとめ、1本の IO コールバックで処理する。同一デバイスならそのまま使う。
- STREAM OUT、MIC MON OUT、CABLE 入力は、それぞれ別のデバイスとして開き、ロックフリーのリングバッファ＋適応リサンプラ（バッファ充填量を目標に保つ）でメインクロックと橋渡しする。
- バッファサイズは 32/64/128/256/512/1024 から選ぶ（既定 128）。

### 3.3 遅延表示チップ（ヘッダー右上）
- 表示例: `CoreAudio · 48k · 128smp · RT 9.8ms`。RT = マイク入力遅延＋出力遅延＋バッファ×2＋FX CHAIN のプラグイン遅延（Core Audio の kAudioDevicePropertyLatency と SafetyOffset を含めて計算）。
- 色: 12ms 以下は緑、12〜20ms はオレンジ、20ms 超は赤。
- `PANEL` ボタン: バッファサイズとサンプルレートを選ぶ小さなダイアログを開く（Windows の ASIO パネル相当）。

## 4. アプリ音声の取り込み（APP モード）

- Core Audio Process Tap を使う（`CATapDescription` を対象プロセスの AudioObjectID 一覧で作成 → `AudioHardwareCreateProcessTap` → tap を含む private aggregate device を作って入力として読む）。
- 一覧: `kAudioHardwarePropertyProcessObjectList` からプロセスを列挙し、bundle id ごとにまとめて表示（Chrome のヘルパーなど子プロセスは親アプリにまとめる。`kAudioProcessPropertyBundleID`、PID からの親子関係）。今音を出していないアプリは名前の後ろに「[音声未検出]」。アイコンとアプリ名を表示。
- 選択画面: チェックボックス一覧、`適用`、`全解除`、`キャンセル`。最大8アプリ、合計16プロセスまで（超えたら理由を表示して止める）。選んだ音はすべて合算して INST とする。
- 選択は bundle id で記憶（設定とプロジェクトの両方に保存）。アプリが終了・再起動したら数秒以内に自動でつなぎ直す（プロセス一覧の変更通知を監視）。
- **直接の音を消す**（Mac 版で追加）: 選択画面に「取り込んだアプリの音をスピーカーから消す」チェック（既定 ON）。ON なら `CATapDescription.muteBehavior = CATapMutedWhenTapped`（取り込み中だけアプリの直接音を消す）。OFF ならコピー（直接音も鳴る）。これで二重に聞こえる問題を設定画面なしで解決する。
- 権限: 初回に「システムオーディオ録音」許可が必要（Info.plist の `NSAudioCaptureUsageDescription` に日本語の説明）。拒否されたら、システム設定の該当画面を開くボタン付きで案内する。マイク許可（`NSMicrophoneUsageDescription`）も同様。
- CABLE モード: INST の入口を入力デバイス（例: BlackHole 2ch）にする。

## 5. OBS への送信

- 配信出力（MASTER・天井の後）を、POSIX 共有メモリ `/klinglab-stream-mixer-v1`（`shm_open`）のロックフリーリングに常時書き込む。STREAM OUT とは独立・併存。
- レイアウト（両側で一致させる。変更時は名前の v を上げる）: 先頭 4096 バイトのヘッダー `{ uint32 magic='KSM1', uint32 version=1, uint32 sampleRate, uint32 channels=2, uint32 capacityFrames=131072(2のべき乗), uint32 _pad, uint64 writePos(フレーム数、単調増加、atomic), uint64 sessionId(起動ごとに乱数) }`、その後 float32 インターリーブのリング本体。
- OBS プラグイン `klinglab-stream-mixer-source`（C、libobs）: 音声ソース「Klinglab Stream Mixer」を追加する。設定項目なし。1秒ごとに共有メモリへの接続を試み、ミキサーが無ければ無音。writePos の巻き戻りか sessionId の変化を見たら再同期。読み遅れが大きいときは最新位置へ飛ぶ。`obs_source_output_audio` で 10ms 単位程度で出す（タイムスタンプは os_gettime_ns 基準）。
- macOS の OBS 30/31（arm64・x86_64）向け `.plugin` バンドル。インストール先 `~/Library/Application Support/obs-studio/plugins/klinglab-stream-mixer-source.plugin`。
- 案内文: OBS 側では元の「マイク」をミュート、「デスクトップ音声」を無効にし、音はこのソース1本にする（ミキサーのメニューの説明に書く）。

## 6. 画面（メインウィンドウ）

既定サイズ 1280×800（最小 1100×720、拡大縮小可、Retina 対応）。明るいベージュ灰色の落ち着いたテーマ。各列に色のドットを付ける: INST INPUT=オレンジ、INST MON=青、STREAM=緑、VOCAL MON=紫、BGM=青緑、SE=ピンク。

### 6.1 ヘッダー
左: ロゴ文字「KLINGLAB STREAM MIXER」。右: `PANEL` ボタン、メニュー（三本線）ボタン、遅延表示チップ。

メニュー項目: チュートリアルをもう一度、使い方（内蔵ヘルプ画面）、声の遅れの調整（PANEL）、BGM と効果音の使い方、配信の音を大きくする（LOUD の使い方）、OBS の設定のしかた、Stream Deck の使い方（プラグイン追加ボタン付き）、設定フォルダを開く、バージョン情報。

### 6.2 上段左ブロック
- PROJECT 行（9章）: プロジェクトのドロップダウン、`1〜9登録`、`新規`、`保存`（黒地）、`別名保存`、`削除`（赤字）。
- デバイス欄 5 行（3章）。
- FX CHAIN 行（8章）: プラグインのボタンが横に並ぶ（左端に並べ替え用のつまみ、名前ボタン、`B`、`X`）。右端に `+ VST`（黒地）と `Scan`。
- STREAM FX 行（13章）: 同じ形のプラグイン列＋`+ VST`。右端に LOUD ブロック（14章）。

### 6.3 上段右ブロック（12章）
- BGM 欄: 見出し「BGM」と件数、`STOP`。1行1曲（番号、名前、くり返しアイコン、長さ）。
- SE 欄: 見出し「SE」と件数、`STOP`。3列のタイル（番号、名前）。

### 6.4 下段（6列のストリップ）
| 列 | 中身 |
|---|---|
| INST INPUT | 入力メーター（ステレオ）。下に MIC NR（つまみ、`NR OFF/ON`、`LEARN/RELEARN`、つまみ値表示） |
| INST MON | メーター＋フェーダー（0.0 dB〜無音、上げ方向なし）、dB 表示 |
| STREAM | 上部に遅延補正 `−` `+0.0 ms` `+`。INST と VOCAL の2本のフェーダー（+6.0 dB〜無音）とメーター（STREAM 合算）。下に横長の MASTER スライダー（+6.0 dB〜無音） |
| VOCAL MON | `MON` スイッチ（黒=ON）、`MON WET` つまみ（0.00〜1.00、既定 1.00）、メーター（エフェクト後の声）、フェーダー（0.0 dB〜無音） |
| BGM | STREAM と MON の2本のフェーダー（+6.0 dB〜無音、既定 −6.0 dB）、`MON` スイッチ、メーター（配信に乗っている BGM） |
| SE | BGM と同じ（既定 −3.1 dB） |

### 6.5 メーター
- dBFS 表示、目盛り 0〜−60 を 6dB きざみ、0 dB に赤い線。
- 色: −6 dB までは列の色、−6〜0 dB は黄、0 dB 超は赤。
- ピークホールド（直近 1.5 秒の最大を細い赤線）、上端にクリップランプ（一度 0 dB に達すると点灯し続け、メーターのクリックで消える）。
- 更新 30fps 以上。音声スレッドからはロックフリーで値だけ渡す。

### 6.6 フェーダー共通
- dB 表示（例 `0.0 dB`、`-6.0 dB`、下端は `-inf`）。ダブルクリックで 0.0 dB。⌥ドラッグで微調整。変更は 20ms 程度でなめらかに補間（ジッパーノイズを出さない）。

### 6.7 番号オーバーレイ
- ⌥N で、画面上のすべての操作部品・文字に固定の番号を重ねて表示（もう一度で消える）。番号は部品の ID から決め、配置が変わっても変わらない。レイアウトに影響しない。

## 7. マイクのノイズ除去（NR）

- マイク声にだけかかる。定常ノイズ（エアコン、ファン）を削る。不規則な音は対象外。
- **先読みなし・遅延 0**: STFT を使わない。IIR のバンド分割（例: 24 バンドの 4 次 Linkwitz–Riley 相当、または位相補正付きフィルタバンク）で、各バンドの包絡を追い、学習したノイズ床に近いバンドだけを下向きエキスパンダーで下げる。合成で位相が崩れて声がこもらないようにする。
- つまみ: 除去量 0〜18 dB（既定 6.0 dB）。0 で原音そのまま。
- `NR OFF/ON`（既定 OFF）。`LEARN`: 押すと約1秒間の入力をノイズとして覚え、表示が `RELEARN` に変わる。学習中は「声を出さないでください」と表示。
- NR の状態と学習結果はプロジェクトに保存。

## 8. プラグイン（FX CHAIN／STREAM FX）

- 形式: VST3 と Audio Unit（macOS 標準）。VST2 は対象外。
- `Scan` メニュー: 「すべて検索し直す」（標準フォルダ `/Library/Audio/Plug-Ins/VST3`、`~/Library/Audio/Plug-Ins/VST3`、AU 一覧）／「フォルダを指定して追加で検索」（選んだフォルダのうち一覧に無いもの・更新されたものだけ）。
  - 検索は**別プロセス**（同じ実行ファイルを `--scan-worker` で起動）で行い、プラグインのクラッシュでミキサーが落ちないようにする。1ファイル 5 分でタイムアウト。進行表示「ファイル名（経過秒）」。
  - 完了時に、読めなかったファイル名を一覧で出す。失敗したものも次回の検索で再挑戦する。
  - 一覧は FX CHAIN と STREAM FX で共通（plugin-list.xml）。
- `+ VST`: 「プラグインを追加」ウィンドウ（検索欄で絞り込み、一覧、`追加`）。
- プラグイン名ボタンで、そのプラグインの画面を別ウィンドウで開く（再度押すと前面へ）。
- `B` = バイパス（オレンジ=ON で効いている／灰=バイパス中、が分かる表示）、`X` = 削除（確認あり。そのプラグインの設定も消える）、左端のつまみでドラッグ並べ替え。
- 何も入っていない列は処理を素通り。
- プラグインの状態（getStateInformation）はプロジェクトに保存。
- **MON WET**（FX CHAIN のみ）: 返し用の声 = 「最後のプラグインの入力」×(1−WET) ＋「最後のプラグインの出力」×WET。配信側は常にフル。プラグインが1つ以下のときは効かない（つまみを灰色にする）。最後のプラグインの遅延分、入力側を遅らせて揃える。
- 重いプラグインで処理が間に合わないときに備え、音声スレッドの処理時間（平均と最大）を計測し、遅延チップの横に負荷 % を小さく出す。

## 9. プロジェクトとショートカット

- プロジェクト = デバイス設定、全フェーダー・スイッチ、NR、FX CHAIN／STREAM FX の構成と各プラグインの状態、APP の選択と「直接の音を消す」、BGM/SE の音量、LOUD の状態（ON/OFF、STREAM/CD、覚えた量）、遅延補正。BGM/SE の一覧そのものは全プロジェクト共通。
- 保存形式: `projects/<名前>.ksmproj`（JSON。プラグイン状態は base64）。
- `新規`（今の設定のまま名前なしで開始）、`保存`（上書き。名前がなければ聞く。「保存しました」を2秒表示）、`別名保存`、`削除`（確認あり）。未保存のときドロップダウンは「（未保存）」。
- 起動時は最後に使った状態を復元。
- `1〜9登録`: 番号 1〜9 に保存済みプロジェクトを割り当てるメニュー。割り当ては全プロジェクト共通（settings.json）。
- グローバルショートカット（ミキサーが背面でも効く。Carbon の `RegisterEventHotKey` を使い、アクセシビリティ許可を要求しない）:
  - ⌃⌥⇧1〜9: その番号のプロジェクトを呼び出す。
  - ⌃⌥⇧F1〜F9: FX CHAIN の上から n 番目のバイパスを切り替える。
- 登録に失敗したら `1〜9登録 !` と表示し、ツールチップで理由（他のソフトが同じキーを使用中）を出す。
- プロジェクト読み込み中はプラグインを裏で用意し、切り替え時に音を途切れさせない（数秒かかってよい）。これはデバイス・サンプルレート・バッファが同じプロジェクト同士の場合。
- デバイス・サンプルレート・バッファが違うプロジェクトへの切り替えでは、0.5 秒以内の途切れを許す（v1.1 改訂）。そのとき BGM・SE は再生位置を保ったまま続きから鳴らし、フェーダー・NR・LOUD などの状態も引き継ぐ。
- 新しいデバイスで開始できなかったとき（デバイスが無い・開けない・Process Tap の再接続失敗）は、デバイス・プラグイン列・設定をすべて切り替え前の状態に戻し、画面に理由を出し、Stream Deck へは LOAD_FAILED を返す。
- 二重起動は禁止（2つ目は既存ウィンドウを前面に出して終了）。

## 10. BGM と効果音

- BGM 欄・SE 欄に Finder からファイルをドラッグして追加（複数可）。対応形式 WAV・MP3・FLAC・OGG・AIFF（AAC/M4A も可）。読めなかったファイルは名前を一覧で表示。
- 追加したファイルは `sounds/` にコピーして使う（元のファイルを消しても鳴る）。
- SE は 3 分まで。超えるものは「BGM 欄に入れてください」と案内して入れない。
- 一覧は全プロジェクト共通。番号は並び順（1から）。
- BGM: 押すと再生、もう一度で停止。同時に1曲。別の曲を押すと前の曲が 1 秒でフェードアウトして入れ替わる。曲ごとの「くり返し」切り替え（丸い矢印、光ると ON）。右端に曲の長さ。`STOP` で 1 秒フェードして停止。
- SE: 押すと鳴る（重ねて鳴らせる、同時 16 まで）。鳴っている間にもう一度押すとその音を止める。`STOP` で全部止める。
- 鳴っている項目は色を付け、進み具合をバーで見せる。
- 名前変更（ホバーで出る鉛筆、または右クリック → その場で編集、Enter で確定、Esc で取消。元ファイル名は変えない）、ドラッグで並べ替え（番号も付け直す）、ホバーで出る × → 確認 → 削除（コピーを消す）。
- 再生は事前にメモリへ読み込むか、別スレッドでストリーミング（音声スレッドでファイルを読まない）。サンプルレートは変換してから鳴らす。

## 11. STREAM FX

- INST＋VOCAL をまとめた後にかかる（8章と同じ操作）。返し（MONITOR）と BGM・SE にはかからない。
- 各プラグインの ON/OFF は Stream Deck からも切り替えられる。

## 12. LOUD

- 目的: 配信の音を YouTube で下げられない大きさ（曲全体で −14 LUFS 前後、サビで −11.5 LUFS 前後）まで上げる。
- 表示: LUFS 値（配信出力の直近 3 秒の short-term ラウドネス、ITU-R BS.1770 の K 特性）。その下に覚えた量（例 `+4.3 dB`）。
- `LEARN`: 押すと「STOP 秒数」表示で測定開始。もう一度押すか 20 秒で終了。測定中の INST＋VOCAL（STREAM FX 後、LOUD 前、MASTER を含めた値）の積分ラウドネスを測り、目標 −11.5 LUFS との差を覚えた量にする。−70 LUFS ゲートより上の音が 3 秒分なければ `TOO QUIET` を表示し、量は前のまま。
- `LOUD ON/OFF`: ON の間、INST＋VOCAL を覚えた量だけ上げる（マイナスなら下げる）。OFF のときは音を一切変えない（天井もかけない）。
- `STREAM` / `CD`（どちらか一方）: CD は STREAM からさらに +4.5 dB（目標 −8 LUFS 前後）。
- 切り替え（ON/OFF、STREAM/CD）は 0.5 秒でなめらかに変える。
- 天井: LOUD ON の間、配信出力全体（BGM・SE を含む）を −1 dBTP を超えないよう、true peak（4 倍オーバーサンプリング）検出・先読み 2〜5 ms のリミッターで抑える。CD モードでは歪みや声の揺れが出にくいよう、前段に穏やかな多段（または 2 段）圧縮を入れてから天井にかける。
- 天井の削り量が STREAM で 3 dB、CD で 7.5 dB を超えたら LUFS 表示をオレンジにする（ツールチップで「MASTER を 0.0 dB に戻す」等の助言）。
- 天井の先読み遅延は配信側だけに入り、返しには入らない。
- 状態はプロジェクトに保存。

## 13. Stream Deck 連携

- ミキサーはローカル WebSocket サーバー（`127.0.0.1:47321`、JSON メッセージ）を持つ。接続時に全状態を送り、変化のたびに差分を送る。Stream Deck 側は「切り替えて」と頼むだけで、表示はミキサーからの知らせで更新する（正はミキサー）。
- Stream Deck プラグイン（Elgato Stream Deck SDK、Node.js、macOS 対応）`site.klinglab.streammixer.sdPlugin`。アクション:
  | アクション | 設定 | 押すと | 表示 |
  |---|---|---|---|
  | FX On/Off | FX CHAIN の番号 1〜9 | バイパス切替 | ON=オレンジのランプ／OFF=灰色 |
  | Project | 1〜9 | そのプロジェクトを呼び出す | 呼び出し中は上にオレンジの帯 |
  | STREAM FX On/Off | 番号 | 切替 | ON=緑のランプ |
  | BGM | 番号 | 再生／停止 | 再生中は青緑の帯 |
  | SE | 番号 | 鳴らす／止める | 鳴っている間ピンクの帯 |
  | Stop Sounds | BGM／SE／両方 | 止める | 対象が鳴っている間オレンジの帯 |
  | LOUD On/Off | — | 切替 | ON の間オレンジの帯 |
  | LOUD Learn | — | 開始／終了 | 測定中は緑の帯と「STOP 秒数」 |
  | LOUD Mode | — | STREAM／CD 切替 | 下に今の強さ。CD の間オレンジ |
- ボタン下の文字は番号と名前（プラグイン名・プロジェクト名・BGM/SE の名前）。番号が空なら「-」、押すと警告マーク（⚠）を一瞬出すだけ。ミキサーが起動していなければ `MIXER OFF`（押しても何もしない。操作をためない）。
- メニューの「Stream Deck の使い方」に「Stream Deck プラグインを追加」ボタン（同梱の .streamDeckPlugin を開く）。

## 14. 初回チュートリアル

- 初回起動時に案内を出す（いつでも「スキップ」できる。メニューから再表示）。手順ごとに対象の部品を光らせる: ①MIC INPUT と MONITOR OUT を選ぶ ②INST INPUT で APP を選び、アプリを選んで INST INPUT メーターが動くのを確認 ③OBS にソースを追加（OBS プラグインの導入状態を表示、未導入なら導入ボタン）、配信メーターが動くのを確認 ④`+ VST` でエフェクトを1つ入れてみる ⑤プロジェクトを保存。
- 各段階の「できた」判定はミキサーが自動で行う（メーターが一定以上動いた、など）。
- 練習用プラグインは同梱しない（実在のプラグインがなければ④は飛ばしてよい）。

## 15. 配布とインストール

- `.pkg` インストーラー: アプリを `/Applications`、OBS プラグインを利用者の `~/Library/Application Support/obs-studio/plugins/`（OBS 起動中なら「OBS を再起動してください」）、Stream Deck プラグインは任意（Stream Deck アプリがあれば導入を案内）。
- 署名: Developer ID がない間は ad-hoc 署名。初回起動時の Gatekeeper の回避手順（右クリック→開く、またはシステム設定→プライバシーとセキュリティ→このまま開く）を説明書に書く。Developer ID が用意できたら署名と公証を行う。
- アンインストール手順を説明書に書く（設定フォルダは残す）。
- 起動ログを `logs/` に残す（ローテーション 5 ファイル）。クラッシュ時は次回起動で知らせる。

## 16. 品質の目安

- 何も入れていない状態の返しの遅延: 48k/128 で RT 12ms 以下（内蔵デバイスの場合は機器の遅延に依存）。
- 音声スレッドでメモリ確保・ロック・ファイル入出力・Objective-C メッセージ送信をしない。
- 8 アプリ取り込み＋FX 2つ＋STREAM FX 2つ＋BGM＋SE 同時で、M1 MacBook Air の CPU 使用率 25% 以下を目安にする。
- スリープ復帰、デバイスの抜き差し、サンプルレート変更で落ちない（該当経路を一時無音にして復帰）。
